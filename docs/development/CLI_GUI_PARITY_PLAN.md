# CLI / GUI 等价性实施与验收计划

以 dev `368c143f739444070a4bce02aa61cec39eff50b4` 为审计基线，工作分支为 `fix/cli-gui-parity`。
目标是让相同工作区、相同输入和相同节点版本，在 CLI 与桌面端产生等价的业务结果。
窗口排列、缩放、主题等纯显示交互无需复制到 CLI；其已有数据必须在 CLI 修改后保留。

## 验收分层与门槛

`test/acceptance/features/` 包含 10 个 feature、89 个场景定义，展开为 177 个用例。
`test/acceptance/contracts.json` 保留稳定 ID、场景标题、变体和期望，Python driver 执行业务并断言可观察结果。
每个已通过用例必须有绑定及非零业务断言。跳过、未绑定、缺失平台或现场证据不能计入完成。

- CLI：`src/cli.py` 与 `src/cli_parity.py` 汇总语句覆盖率 ≥85%，分支覆盖率 ≥75%。
- 新核心服务：workflow_lifecycle、execution_snapshots、playwright_runtime、config_transactions 汇总语句 ≥90%，分支 ≥85%。
- 性能测试独立运行，不使用 coverage。全量功能测试、feature 验收、覆盖率和性能均须成功。
- 发布使用同一个源提交的 Linux 与 Windows 最新成功 CI；旧提交成功不能放行。
- Windows 成品和现场验收独立记录；源码层通过不代表已通过成品或现场验证。

## 执行方式

详见 [验收 README](../../test/acceptance/README.md)。开发环境执行离线 cohort，Windows CI 增加原生平台保存检查。
成品验收使用实际 exe/MSI/ZIP 的 SHA-256 和源提交，移除子进程 PATH 中的开发 Python。
Windows CI 新增真实构建及安装验收 job，自动运行 DIST_001–004 的 6 个展开用例，不执行发布。
可自动化的成品命令直接执行；需要 GUI 操作、MSI 安装和真实 Chrome 的用例按现场清单录制证据。

## 当前状态与交付原则

生命周期、配置事务、编辑/执行、显式复用、AI 示例/版本、任务目标、独立录制环境已实现。
离线 feature 164/164 通过；完整离线回归 760 项通过，CLI 与新核心服务的语句、分支覆盖率均达标。
详细结果见 [验证记录](CLI_GUI_PARITY_VALIDATION.md)。
当前 Linux 环境没有 Windows 成品安装主机及隔离的外部测试账号，13 个平台/现场变体保持待验收。
最终状态以测试生成的 acceptance JSON 和覆盖率 JSON 为准，不以此文档或历史“完成”报告代替证据。

交付需包含实现提交、测试、feature、可复跑命令和阻塞说明；未经证据验证的项不得标记完成。
